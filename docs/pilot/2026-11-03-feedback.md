# 第一次 pilot 的反馈，2026-11-03

这份文档收 2026-11-03 第一次 pilot 的实验员反馈，按谁来改分节：实验流程由实验员和眼镜端改，系统问题和 agent 行为由这个仓库改，控制台和实验配置由 QoE Lab 那边改。数据分析在 `2026-11-03-analysis.md`。


## 实验流程和指导语

- 开始前的指令要明确：什么任务、做什么、几分钟、能干什么、能问什么。
- 要说明启动等待也算在时限里，网络延迟高的时候启动本身就慢。
- 三分钟不太够，上限估计要写成五分钟。
- 一开始就要告知参与者每场有时长上限、到时会自动退出，这些都是正常的。
- 拆乐高放在做问卷之前，并且一定要提醒，这样系统自动进下一步也不会出问题。
- ready 按钮倾向不做，但流程要提前讲清。
- 做完要双击退出，但要防止被试误触退出 lab 模式或退到桌面。
- 每条要分清哪些放眼镜里提示（拆乐高、做问卷等），哪些由实验员口头说。
- 问卷里 vision_hearing_ok 这一题（能否看清显示、听清声音）的措辞要改，被试答了 No。

## 系统问题

- 眼镜 app 中途崩了一次退回桌面，原因不明，是正式第 2 场（run 4，mushroom），控制台一直等到 253.8 s。
- 曝光值忘了改成 -6。
- 电池撑不到 7 轮，要插线跑。

## Agent 行为

- 考虑去掉大脑的 look（语音转交后拍一张再答），只留 watch（每两秒自己看），体感 look 忽快忽慢，宁可一致。
- 系统主动提出看图时，错一次就问，不要等三次。
- 被试觉得系统太沉默：拿起正确的颗粒时大脑在日志里看到了也确认了，但正确的事只走 tell（不出声），voice 就不说话，被试没有反馈，觉得系统迟钝。

## 控制台（QoE Lab 那边要改的）

- 训练 run 也要能自动 advance，现在只有正式 run 会。
- 考虑把每轮开始前的用户确认加回来，不然被试容易措手不及。
- demographics 问卷也放到 rating client 的界面上，被试不应看到控制台界面。
- 被试坐在桌前，左边是 netem 机器、右边是乐高，实验员要操作就得伸手过去。
- 考虑做网页版的控制台前端，实验员在自己的机器上监控，不用碰给被试做问卷的 netem 机器。
- 抓包在场结束时没有停，四个 pcap 都录到导出前，captures.csv 的 packets 是 0，见 `2026-11-03-analysis.md` 开头。

## 实验配置（控制台里改设置）

- 每场时长上限从 180 s 改到约 300 s。
- vision_hearing_ok 这一题改措辞。
